## 2024-10-30 - [Content Security Policy constraints in offline apps]
**Vulnerability:** Missing Content Security Policy (CSP). Without a CSP, the application is highly vulnerable to Cross-Site Scripting (XSS) if user input is mishandled.
**Learning:** The application architecture heavily relies on inline event handlers (like `onclick='...'` in `innerHTML`) and inline styles. Because of this architectural constraint, setting a strict CSP is challenging because we are forced to allow `'unsafe-inline'` for both scripts and styles, weakening XSS mitigation. However, since the app is fully offline, we can strictly enforce `connect-src 'self'` to completely eliminate data exfiltration risks to external servers if XSS somehow occurs.
**Prevention:** Always define a Content Security Policy as a fundamental layer of defense. In apps using inline scripts/styles out of necessity, drastically restrict `connect-src`, `object-src`, and `default-src` to contain the damage of an injection attack. Future refactors should aim to move inline event listeners to the Javascript file (via `addEventListener`) to allow removing `'unsafe-inline'` from `script-src`.
