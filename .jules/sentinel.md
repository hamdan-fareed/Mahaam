## 2024-05-18 - Missing CSP & DOM XSS via Unescaped Date
**Vulnerability:** The Electron application lacked a Content-Security-Policy (CSP) meta tag, making it vulnerable to XSS if malicious scripts are loaded. Furthermore, user-controlled data such as `task.dueDate` and `entry.date` injected into the DOM via `innerHTML` were not passed through `escapeHtml`, leaving the application vulnerable to DOM XSS. For instance, if an attacker could manipulate `localStorage` entries (a potential vector for client-side attacks), they could trigger JavaScript execution.
**Learning:** `formatDisplayDate` returns raw strings that were assumed to be safe dates but could contain malicious payloads if the input is malformed or maliciously tampered with in storage. Electron applications must have a strict CSP to mitigate such XSS risks and prevent unintended data exfiltration or script execution.
**Prevention:** Always enforce a strict `Content-Security-Policy` via meta tags in HTML files. Always sanitize or escape any data injected directly into `innerHTML`, regardless of whether the source is considered "trusted" like a date field or local storage.
