## 2024-03-01 - CSP constraints with Vanilla JS architecture
**Vulnerability:** Missing Content Security Policy (CSP) allowed potential data exfiltration and inline script execution if an injection point was found.
**Learning:** The application heavily relies on vanilla JS with inline event handlers (`onclick="..."` etc.) and inline styling for dynamic elements (charts/bars). A strict CSP like `default-src 'self'` immediately broke core functionality due to these architectural constraints.
**Prevention:** To secure the app without a total rewrite, implemented a pragmatic CSP: `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self' data:; font-src 'self' data:;`. This restricts external connections and exfiltration while permitting the necessary inline scripts/styles for the current architecture. For future development, refactoring away from inline handlers should be considered to allow removing `'unsafe-inline'`.
