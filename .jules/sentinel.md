## 2024-05-18 - [MEDIUM] Added strict Content-Security-Policy (CSP) to mitigate potential data exfiltration
**Vulnerability:** The application was missing a Content-Security-Policy header/meta tag. While fully offline, if an XSS vulnerability was introduced elsewhere, attackers could potentially exfiltrate data (like tasks or habits stored in localStorage) to an external server.
**Learning:** The application architecture relies on inline event handlers (e.g., `onclick='app.toggleTask(...)'`) and inline styles (e.g., updating canvas dimensions). Therefore, `'unsafe-inline'` for `script-src` and `style-src` is currently required to not break core functionality. We learned that `connect-src 'self'` is the crucial directive here for an offline app, ensuring any malicious fetch or XHR requests to external domains are blocked.
**Prevention:** Always define a Content Security Policy for Electron applications, even if they operate offline. When inline scripts/styles must be used due to legacy architecture, explicitly restrict `connect-src` to `'self'` to prevent data leakage over the network.
