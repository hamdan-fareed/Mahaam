## 2026-10-31 - [Enforcing Offline-First Constraints via CSP]
**Vulnerability:** The application was intended to be fully offline-first, but lacked a Content Security Policy (CSP) to strictly enforce this at the browser level. Without a CSP, if an attacker managed to inject malicious code (e.g., via a cross-site scripting vulnerability that slipped through `escapeHtml`), the script could potentially exfiltrate sensitive local task or habit data to an external server.
**Learning:** Even desktop (Electron) and mobile wrapper applications that only intend to use local data need a CSP. Because the app uses inline event handlers (e.g., `onclick="app.openEditModal('...')"` in `src/app.js`) and inline styles, the policy must allow `'unsafe-inline'` for `script-src` and `style-src`. The critical protection here is restricting the `connect-src` and `default-src` to `'self'` (or limiting them entirely), completely blocking outbound network requests from the renderer process.
**Prevention:** Always implement a strict CSP by default in new projects, tailoring the directives (like `connect-src 'self'`) to match the application's intended architectural constraints. When relying on offline-first architectures, the CSP is a crucial layer of defense against data exfiltration.
